# ExperienceGraph 重构草案（初稿）

## 1. 背景与目标

我们计划重构 ExperienceGraph，使其在以下情况下仍能提供有价值的经验：

- 当前状态无法与图中已有节点精确对应
- 历史经验不是完全同构，但语义上与当前问题接近
- 图规模增大后，需要更高效地找到可能有帮助的经验路径

本次重构的目标不是替代图结构，而是增强图结构的检索与规划能力：

- 保留显式图上的节点、边、路径和图搜索
- 引入 embedding 作为检索层与启发式层
- 在没有精确匹配节点时，仍然能提供“方向性经验”，而不是完全退化为无经验决策

一句话概括：

> 不是“在高维空间里直接寻路”，而是“在显式图上寻路，但用 embedding 作为启发式和检索层”。

## 2. 核心设计思想

ExperienceGraph 的主体仍然是显式经验图：

- 节点表示状态性经验节点
- 边表示历史积累的可执行 experience
- 路径表示从某个起点到某个目标节点的历史经验组合
- 实际规划仍然通过图论方法在图上完成

embedding 的作用不是替代节点、边和路径，而是补充两个能力：

1. 当当前状态无法精确绑定到已有节点时，从语义上找到几个最接近的历史节点，作为近似参考入口
2. 在图搜索过程中，为搜索算法提供 heuristic，加速找到更有希望的路径

因此，embedding 负责“找方向”，图结构负责“判断怎么走”。

## 3. 设计原则

### 3.1 显式图仍是主体

- 规划发生在显式图上
- 可执行性由 edge、precondition、graph connectivity 等结构化信息决定
- embedding 不能直接替代状态转移关系

### 3.2 Exact Binding 优先，Semantic Fallback 次之

检索机制建议分成两层：

1. `Exact binding`
   当前状态可以精确对应到已有节点时，直接把该节点作为起点，在图上搜索到目标节点的候选路径。

2. `Semantic fallback`
   当前状态无法精确对应到已有节点时，使用 embedding 检索 top-k 个语义近邻节点，将其作为代理锚点，再在显式图上搜索这些锚点通向目标节点的候选路径。

这一层的作用不是声称“当前状态等于这些近邻节点”，而是提供模糊但有用的参考入口。

### 3.3 语义相似性不等于可执行性

embedding 空间中的距离表达的是语义相似性，而不是：

- 图上必然可达
- 当前前置条件已经满足
- 一定存在合法 action sequence

因此必须区分：

- `semantic proximity`
- `action reachability`

前者适合做检索与启发，后者必须由图结构和环境约束决定。

## 4. 基本流程

### 4.1 Goal 处理

1. 用户输入 goal
2. 使用 LLM 将 goal 标准化为一句 canonical goal
3. 将 canonical goal 转成 embedding
4. 在已有 goal/node 空间中检索 top-k 语义近邻
5. 判断这些近邻中是否已有与当前 goal 对应的节点
6. 若没有，则创建新节点

这一流程主要用于：

- goal 归一化
- 减少表述差异导致的重复节点
- 为后续规划提供更稳定的目标表示

### 4.2 执行前的经验检索

在每次 LLM 执行动作前：

1. 尝试将当前状态精确绑定到已有节点
2. 若绑定成功，则直接从当前节点到目标节点进行图搜索
3. 若绑定失败，则对当前状态做 embedding，检索 top-k 个语义近邻节点
4. 将这些近邻节点视为代理锚点或模糊参考入口
5. 在显式图中，从这些锚点通向目标节点搜索候选路径
6. 返回 top-k 条候选路径作为经验输入给 LLM

这样做的重点是：

- 没有精确匹配时，也能获得方向性经验
- 检索到的是“可能有帮助的参考入口”，不是“当前状态已经等于该节点”

## 5. 节点 embedding 的定位

本方案当前只要求对节点进行 embedding，不要求把整条路径作为主要对象进行 embedding。

原因是：

- 节点 embedding 更适合表达状态语义或目标语义
- 路径更适合继续由显式 edge sequence 表示
- 保留显式路径有更强的可解释性，也更便于调试和分析

因此，本方案的重点是：

- `node embedding + symbolic edges + graph search`

而不是：

- `pure vector retrieval over trajectories`

## 6. “高维空间中寻路”的准确含义

“高维空间中寻路”在本方案里应理解为：

- embedding 用来估计某个节点与目标节点的语义接近程度
- 这种语义距离可以作为图搜索时的 heuristic 或排序信号
- 真正的搜索仍然在显式图上进行

也就是说，本方案是：

- `embedding-guided graph search`

而不是：

- 直接把向量空间里的邻近关系当成状态转移关系

## 7. A* 与 heuristic 的结合

embedding 的一个重要用途，是给图搜索提供 heuristic。

例如，在已知目标节点 `g` 时，可以定义：

- `g(n)`：从当前起点到节点 `n` 的实际路径代价
- `h(n)`：节点 `n` 与目标节点 `g` 的 embedding 距离
- `f(n) = g(n) + h(n)`

这可以自然用于 A* 或类似搜索算法中。

它的价值包括：

- 在图较大时减少无效搜索
- 优先扩展更接近目标语义的节点
- 将历史经验图与经典图搜索方法结合

需要强调的是，`h(n)` 只是启发式，不是可执行性判断。

## 8. Goal 与 State 的文本化和向量化

我们不希望自己训练模型，因此采用现成 embedding 模型，通过稳定文本模板获得向量。

### 8.1 Goal Embedding

先把用户输入的 goal 标准化成一句 canonical goal，例如：

- `craft a full diamond armor set`
- `reach a state where diamond_set can be crafted`

然后将这句文本送入现成 embedding 模型。

这里的关键不是模型本身，而是 goal 表达要稳定，避免同一个目标被压成风格差异很大的文本。

### 8.2 State Embedding

state 不建议直接使用原始 dict，而应先做 canonical serialization，再转成文本。

推荐包含：

- 当前 task
- 当前 location
- inventory
- tools
- 已知环境事实
- 与当前 goal 相关的关键缺失条件

这样做的好处是：

- 表达稳定
- 相似状态更容易获得相近向量
- 更利于语义检索

## 9. 现成 embedding 方案

我们不自己训练模型，优先采用现成方案。

### 9.1 API 方案

- OpenAI embedding 模型
- 优点是接入简单、效果稳定、工程成本低
- 适合快速验证检索机制

### 9.2 本地开源方案

可优先评估：

- `multilingual-e5-large-instruct`
- `bge-m3`
- `all-mpnet-base-v2`
- `all-MiniLM-L6-v2`

初步建议：

- 若需要处理中英混合、偏检索任务，优先考虑 `multilingual-e5-large-instruct` 或 `bge-m3`
- 若需要轻量本地 baseline，可先试 `all-MiniLM-L6-v2`

## 10. 本方案解决的核心问题

### 10.1 避免“无精确匹配就完全无经验”

传统精确匹配下，如果当前状态没有对应节点，系统往往无法提取任何经验。引入 semantic fallback 后，系统至少可以找到语义上最接近的几个参考入口，并继续在图中搜索有帮助的路径。

### 10.2 让经验图具备“模糊方向感”

即使当前状态与历史状态不完全一致，也可能与某些历史节点共享相似的资源结构、阶段位置或目标趋向。embedding 检索可以把这种语义邻近性转化为可利用的经验线索。

### 10.3 提升图搜索效率

当图规模增长时，仅靠无启发的搜索代价较高。embedding 可以作为 heuristic，引导搜索优先访问更接近目标语义的节点。

## 11. 当前边界

本草案当前不主张以下做法：

- 不主张用 embedding 直接替代图结构
- 不主张把向量空间邻近直接视为可执行转移
- 不主张暂时让路径检索完全脱离显式 edge sequence
- 不主张让 LLM 单独决定节点是否等价，而不受规则约束

当前更稳妥的设计边界是：

- embedding 负责检索与启发
- graph 负责结构、约束与可执行性
- LLM 负责生成、判断和利用经验，但不是唯一裁决者

## 12. 后续需要继续明确的问题

1. goal node 和 state node 是否要严格分层，还是先统一为一种 node 类型
2. 当前状态的“精确绑定失败”如何定义
3. semantic fallback 检索的 query 应以 state 为主，还是 goal 与 state 联合构造
4. 多个语义近邻节点的路径如何合并、去重、排序
5. embedding heuristic 如何与成功率、路径长度、前置条件缺失一起进入最终路径评分
6. LLM 在“已有节点 / 新建节点”判定中的角色边界如何定义
